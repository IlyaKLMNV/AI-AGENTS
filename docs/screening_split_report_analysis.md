# Как анализировать отчёт `screening_split` после прогона

Практический плейбук: отличить **реальный баг промпта** от **шума харнесса**, атрибутировать ошибку
(Аналитик / Интервьюер), поймать **неверный вердикт** (твой факт ≠ отчёт) и разрулить его.

Собрано из находок ревью `170200` — и тех, что нашёл ты, и тех, что нашёл я. Всё на русском, отчёты — UTF-8.

---

## 0. TL;DR — порядок чтения (5 шагов)

1. **`metrics.json` → `summary`**: `passed/failed` = качество промпта; `errors` = инфра (НЕ баг промпта).
2. **Режим гейта каждого кейса** (`verdict.evaluator: "screening_split (gate:X)"`) — от него зависит, **что значит `passed`** (см. §2). В `signal` верхний `passed` НЕ про Аналитика.
3. **Для каждого fail (и подозрительного pass)** — прогони дерево триажа §4.
4. **Расхождение «твой факт ≠ отчёт»** — маршрутизируй по таблице §5 (это НЕ всегда «судья»).
5. Собери находки по направлениям §7 (rounds / инвариант / генератор / эпик E / counter / эпик F).

## 1. Три файла отчёта

`tests/reports_v2/screening_split/<runId>.*`:
- **`*.metrics.json`** — агрегаты (`summary` + кастомные счётчики). Читать первым.
- **`*.cases.json`** — по кейсам: транскрипт, чеки, вердикт, атрибуция. Основной разбор — тут.
- **`*.review.md`** — у `screening_split` **отключён** (`write_review=False`): человекочитаемость даёт `cases.json`.

### `summary` (metrics.json)
- `passed` / `failed` — **качество промпта** (прошёл ли сценарий).
- `errors` — **инфра-сбои** (timeout / auth / SSL / http / `empty_dialogue`). **НЕ в `failed`.** Это не баг промпта — перезапустить.
- `total` = passed + failed (без errors и без `skipped_no_examples`).

### Кастомные счётчики (metrics.json) — сигналы, а не приговор
| Счётчик | Значит |
|---|---|
| `analyzer_fail` | Инвариант Аналитика провален **и ГЕЙТИЛ** (scripted). Реальный минус Аналитика. |
| `analyzer_flag_generate` | Инвариант провален, но НЕ гейтил (generated=signal). **Замаскированный** сигнал — смотри вручную. |
| `analyzer_leak` / `interviewer_leak` | Утечка секрета (число вилки / ссылка при скрытом) — с атрибуцией вины. |
| `interviewer_fail` | LLM-судья Интервьюера завалил (текст не соответствует инструкции Аналитика). |
| `skipped_no_examples` | Нет реплик кандидата (golden без примеров) — не прогонялся, не баг. |

## 2. Режим гейта — читать ПЕРВЫМ

Гейт выбирается по (режим входа × есть ли инвариант в `scenario_checks.yaml`). **`passed` в разных гейтах значит РАЗНОЕ:**

| Вход | Инвариант | Гейт | `core_ok` = | Что значит `passed` |
|---|---|---|---|---|
| scripted | есть | **`analyzer`** | инвариант Аналитика | Аналитик корректен (жёсткий детерминированный гейт). **Доверяй.** |
| scripted | нет | `dialogue` | ScenarioJudge (LLM) | Мнение LLM-судьи диалога. Перепроверяй (шумно). |
| generated | есть | **`signal`** | `True` (!) | «нет утечки + Интервьюер ок». **Аналитик — лишь СИГНАЛ, не гейтит.** |
| generated | нет | `dialogue` | ScenarioJudge | Мнение LLM-судьи. Перепроверяй. |

Итог всегда: `passed = core_ok AND leak_ok AND interviewer_ok`.

> ⚠ **Главная ловушка (кейс 6).** В `signal` Аналитик мог **завалить** инвариант, а кейс всё равно `passed=true`
> (leak+Интервьюер ок). Провал Аналитика тогда лежит в `analyzer_flag_generate` и в чеке кейса
> **«Аналитик: инварианты Decision (сигнал)» → passed:false**. Не читай `passed` как «Аналитик прав» в generated.
>
> **Хочешь жёсткий вердикт Аналитика — гоняй `--input-mode scripted`** (gate=analyzer): там инвариант гейтит.

## 3. Структура кейса (`cases.json`)

```
case_id            "scenario:34:v2:<полное имя>"  (variant 1-based; v-метка только в generated)
passed             итог кейса (см. §2)
inputs.input_mode  scripted | generated | golden | generate
inputs.criterion   expected_behavior сценария (из CSV) — «эталон смысла»
transcript[]       чередование candidate / assistant по раундам:
   role=assistant: text (что РЕАЛЬНО ушло) · turn_kind (script|interviewer_reply|fallback)
                   analyzer_instruction (что ВЕЛЕЛ Аналитик) · decision (Decision) · state · ended
checks[]           {rule, passed, detail} — по слоям (Аналитик-инвариант / утечка / Интервьюер-LLM)
verdict            evaluator="screening_split (gate:X)" · reason_codes[] (с тегами [Аналитик]/[Интервьюер]) · comment
```

**Атрибуция роли — ключ к разбору Интервьюера:** сравни `analyzer_instruction` (что велел Аналитик) с
`text` (что сказал Интервьюер).
- Инструкция верная, текст — мимо → **вина Интервьюера**.
- Инструкция уже кривая → **вина Аналитика** (Интервьюер лишь озвучил).
- `turn_kind=script` → текст детерминированный (реестр скриптов), Интервьюер не при чём.

Утечка (`leak`) осмысленна только если Интервьюер **говорил** (был `turn_kind=interviewer_reply`); на чистых
скриптах канарейка не применяется.

## 4. Триаж одного кейса — дерево решений

Прогоняй сверху вниз для каждого `failed` **И** каждого подозрительного `passed`:

1. **Инфра?** `call_error` в кейсе / рост `summary.errors` (SSL/timeout/auth/`empty_dialogue`). → не баг промпта, **перезапусти** (транзиент лечится повтором).
2. **Раунды?** Сколько обменов в `transcript`? Сверь с рецептом (`candidate_inputs.yaml: rounds`/`len(turns)`).
   Лишние раунды → **reask-cap → форс STOP** → ломается `expect_end:false`/`expect_last_asking`. Это **артефакт драйвера**, не промпт (после батча 1 не должно всплывать; если всплыло — рецепт задаёт больше раундов, чем нужно).
3. **Гейт?** (§2). Если `gate:signal` и `passed=true` — **обязательно** глянь чек «Аналитик … (сигнал)»: там может быть скрытый провал Аналитика (кейс 6). Верхний `passed` в signal ≠ Аналитик прав.
4. **Атрибуция.** `reason_codes` уже размечены `[Аналитик]`/`[Интервьюер]`. Для Интервьюера — сверь `analyzer_instruction` vs `text` (§3).
5. **Контекст подставлен верно?** Тест должен ассертить **вход**, а не только исход:
   - источник контакта: в тексте конкретный (`«резюме HH»`), а не fallback `«из базы»` (кейс 40 — `source_type`, НЕ `contact_source`);
   - вилка реально ушла в Аналитик (`build_context: «Зарплатная вилка: …»`);
   - скрытость: `company_name: СКРЫТО` уходит в Аналитик (кейс 23) — если формулировка не та, это **выбор Аналитика (E)**, а не баг контекста.
6. **Генератор-шум?** (только generated) Кандидат несёт лишнее/«литературщину», случайную сумму/город?
   → слабый сид, **не баг промпта**. Лечится тугим `must_convey`/`salary_category`/`convey` (батч 1) или уходом в scripted.
7. **Реальный вердикт vs твой факт.** Осталось расхождение → §5.

## 5. Расхождение «твой факт ≠ отчёт» — что чинить (ответ на «менять судью?»)

**Твой вердикт = истина.** Отчёт разошёлся → баг в ХАРНЕССЕ или ПРОМПТЕ. «Доверяем судье» — не бывает.
Что именно править — по тому, **кто решал** кейс:

| Кто вынес вердикт (гейт) | Расхождение чиним так |
|---|---|
| **Инвариант, слой A** (`gate:analyzer`) | Правим `scenario_checks.yaml` — спека ожидания слишком строгая/слабая. НЕ «судья». |
| **Аналитик реально неправ** (инвариант поймал верно) | FALSE **корректен**. Баг **промпта Аналитика** → **эпик E**. Харнесс сработал. |
| **`signal` замаскировал** (generated, `passed` при провале Аналитика) | Не вердикт-баг: перегони **scripted** для жёсткого гейта; провал уже виден в `analyzer_flag_generate`. |
| **ScenarioJudge, слой C** (`gate:dialogue`, LLM) | **Конвертировать сценарий в детерминированный инвариант** (добавить запись в `scenario_checks.yaml` + рецепт) — убить судью для него. Тюнинг ScenarioJudge — крайний случай. |
| **InterviewerJudge, слой B** (LLM, качество текста) | Инструкция Аналитика была верной, а судья ошибся с текстом → правим **рубрику InterviewerJudge** ИЛИ добавляем детерминированный маркер-чек (например, «есть/нет запретной фразы»). |

Приоритет редизайна: **детерминированный инвариант > LLM-судья.** Каждое расхождение под ScenarioJudge —
повод перевести сценарий в слой A, а не «подкрутить» LLM.

## 6. Чеклист типовых грабель (found + missed)

- [ ] **`passed` в generated ≠ «Аналитик прав»** — это `signal`; смотри чек-сигнал Аналитика. *(кейс 6)*
- [ ] **Лишние раунды → reask-cap → STOP → ложный FALSE.** Сверь round с рецептом. *(46/47/48, 12)* — лечится `rounds`.
- [ ] **Источник контакта**: движок читает `source_type` (не `contact_source`); ассертить конкретный источник `«резюме HH»` ≠ `«из базы»`. *(40)*
- [ ] **Скрытость**: `СКРЫТО` уходит в Аналитик → формулировка «не раскрою» = выбор Аналитика (эпик E), не баг контекста. *(23)*
- [ ] **Повтор вопроса про компанию — счётчика НЕТ** (`COUNTER_KEYS` без `company_info`) → диалог может не закрыться. Нужен **универсальный счётчик повторов** (движок tgApi). *(24, 22)*
- [ ] **Генератор без контекста вакансии** → случайная сумма/город = шум. Лечится `salary_category`/`convey`. *(32, 34)*
- [ ] **Отсебятина Аналитика** (бонусы), обращение «ты» вместо «Вы», род («готов» без «(а)») → баг **промпта** (E), не харнесс. *(9, 12, 3, 34)*
- [ ] **Триггер не распознан** (informal/absurd 6, grief 38, глобальное «не мой профиль» 25) → Аналитик не эмитит нужный event/script → **эпик E**; в generated это ещё и маскируется (signal).
- [ ] **Потеря смысла Интервьюером** (не сохранил «ваш ответ не совсем понятен») → контракт Аналитик↔Интервьюер (must-keep) — E. *(3v1, 26)*
- [ ] **Утечку читаем только если Интервьюер говорил** (`turn_kind=interviewer_reply`); на скрипте канарейка не применяется.

## 7. Куда роутить находку

| Направление | Что туда идёт |
|---|---|
| **Рецепт/раунды** (`candidate_inputs.yaml`) | Лишние/недостающие раунды; хореография chain; чистый сид. |
| **Инвариант** (`scenario_checks.yaml`) | Спека ожидания неверна; перевод сценария из dialogue → детерминированный слой A. |
| **Генератор** (`must_convey`/`salary_category`/`convey` + `fixtures/generation`) | Шум, случайная магнитуда/город, слабая критика. |
| **Эпик E** (repo `prompts`) | Реальные баги Аналитика/Интервьюера: «Вы»/род, отсебятина, скрытый-поиск фраза, формат-фраза, триггеры, gross→net, контракт двух промптов. |
| **Counter-test + движок** (tgApi) | Универсальный счётчик повторов (кейс 22); пороговые STOP отдельным тестом. |
| **Эпик F — точность вердиктов** | Сверка отчёт↔твой факт после каждого прогона; правка инварианта / конверт в слой A / рубрика судьи (§5). |

## Приложение. Быстрые ссылки на код

- Логика гейта и вердикта: `runners/screening_split.py` → `_fold` (`gate`, `core_ok`, `passed`), `_gate_for`.
- Инварианты слоя A: `domain/screening_split/checks.py` → `evaluate_analyzer` (`expect_*`).
- Утечка слоя B: `checks.py` → `leak_scan` (атрибуция `culprit`).
- Скрипты (верболтим-ответы): `domain/screening_split/scripts.py`.
- Пороги счётчиков (форс STOP кодом): `engine.py` → `_EVENT_STOP`, `COUNTER_KEYS` в `state.py`.

Консольные теги прогона: `A:ok|A:FAIL|A:flag` (Аналитик: гейтил-ок / гейтил-провал / только сигнал),
`B:FAIL` (утечка или Интервьюер), `[scr|gen*|gen|gld]` (режим входа), `turns=N`, `fb=N` (fallback генератора).
